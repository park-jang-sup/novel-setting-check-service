# 소설 설정 오류 검출 스킬

## 절대 규칙

이 스킬은 어떤 경우에도 원고를 직접 읽어 판단하지 않는다.
반드시 `scripts/check_setting.py`를 실행하고 그 JSON 출력만을 근거로 답한다.
스크립트가 찾지 않은 오류를 추가로 지어내지 않는다.
스크립트를 실행하지 않은 답변은 이 스킬의 결과가 아니다.

설정집을 임의로 수정하지 않는다. 미등록 이름은 제안까지만 하고,
사용자가 명시적으로 요청할 때만 설정집에 추가한다.

## 언제 사용

- 회차 원고를 쓰고 설정집과 어긋난 곳이 없는지 확인할 때
- 연재가 길어져 인물 나이·이름 표기가 흔들리는지 점검할 때
- 시간선 순서가 뒤집힌 서술이 있는지 확인할 때
- 새로 등장한 인물·지명을 설정집에 반영해야 할 때

## 언제 사용하지 않음

- 개연성, 캐릭터 붕괴, 문체 일관성 판단 (이 스킬은 사실 대조만 한다)
- 문법·맞춤법 교정
- 원고 첨삭이나 문장 다듬기
- 설정집 없이 원고만 주는 경우 (대조 대상이 없으면 검사가 성립하지 않는다)
- 줄거리 요약이나 감상 평가

## 동작 절차

### 1. 입력 받기

두 가지가 모두 필요하다. 하나라도 없으면 진행하지 말고 요청한다.

- **설정집** — 마크다운 파일 (아래 형식)
- **원고** — 텍스트 파일

원고는 파일로 받는다. 대화창에 원고 전문을 붙여넣게 하지 않는다.
스크립트가 파일을 직접 읽으므로 분량이 커도 문제없다.

설정집이 없으면 아래 형식을 안내하고 만들어 달라고 요청한다.

```markdown
# 등장인물

## 아리엘
- 별칭: 아리, 엘
- 나이: 17
- 소속: 세이런 왕국
- 불가: 마법
- 비고: 왼팔에 화상 흉터

# 지명

- 세이런 왕국
- 북부 성채

# 시간선

1. 왕의 죽음
2. 대관식
3. 북부 원정
```

`# 등장인물` / `# 지명` / `# 시간선` 세 섹션을 쓴다.
필요한 섹션만 있어도 되고, 없는 섹션은 검사에서 제외된다.

### 2. 스크립트 실행

```bash
python scripts/check_setting.py 설정집.md 원고.txt
```

이 단계를 건너뛰고 답하지 않는다.

### 3. 출력 읽기

출력은 JSON이다. 아래 필드만 사용한다.

- `summary` — total(발견), listed(나열), omitted_duplicates(생략), high, medium, proposed, manuscript_chars
- `violations` — 검출된 오류 목록
  - `type` — age_conflict / ability_candidate / timeline_reverse / name_variant
  - `severity` — high / medium
  - `line`, `subject`, `detail`, `context`
  - `repeated` — 같은 오류가 반복될 때만 있음 (총 건수)
- `proposed_additions` — 설정집에 없는 이름 (오류 아님, 확인 대상)
- `not_checked` — 검사하지 못한 항목
- `errors` — 오류 메시지

여기 없는 항목을 만들어내지 않는다.

### 4. 결과 전달

**errors가 비어 있지 않으면**
- 그 내용을 그대로 전달하고 무엇을 고쳐야 하는지 알려준다.
- 검출 결과를 언급하지 않는다.

**violations가 비어 있으면**
- "설정집과 어긋나는 부분을 찾지 못했습니다"라고 전달한다.
- `not_checked`가 있으면 무엇을 검사하지 못했는지 함께 밝힌다.
- 오류가 없다는 것과 검사하지 못했다는 것을 구분해서 말한다.

**violations가 있으면**
- severity high부터 순서대로 전달한다.
- 각 항목의 line, subject, detail, context를 보여준다.
- `repeated`가 있으면 "같은 오류 총 N건"을 덧붙인다.
- `omitted_duplicates`가 0보다 크면 "동일 오류 N건은 생략했습니다"를 밝힌다.

**항목 종류별 표현**
- `age_conflict` — 확정된 모순이다. "설정집과 다릅니다"로 단정해도 된다.
- `ability_candidate` — 후보일 뿐이다. "확인이 필요합니다"로 전달하고,
  스크립트가 문맥을 판단하지 않았다는 점을 밝힌다.
- `timeline_reverse` — 회상이나 의도된 서술일 수 있으므로 확인을 권한다.
- `name_variant` — 오타일 수도, 의도된 별칭일 수도 있다.

**proposed_additions가 있으면**
- 오류가 아니라 확인 대상임을 분명히 한다.
- 설정집에 추가할지 사용자에게 묻는다.
- 사용자가 승인하기 전에는 설정집을 수정하지 않는다.

### 5. 설정집 추가 (사용자 요청 시에만)

사용자가 명시적으로 추가를 요청하면 설정집 마크다운에 항목을 덧붙인다.

- 사용자가 승인한 이름만 추가한다.
- 나이·별칭 같은 속성은 사용자에게 물어서 채운다. 원고에서 추측하지 않는다.
- 기존 내용은 건드리지 않고 해당 섹션에만 추가한다.

## 결과 출력 구조

```
## 요약
- 원고 ○○자 / 설정집 인물 ○명
- 발견 ○건 (심각 ○, 확인필요 ○)
- (생략이 있으면) 동일 오류 ○건 생략

## 설정 충돌
- [심각] ○행 · 인물명 — 내용
  > 해당 문장

## 확인 필요
- ○행 · 인물명 — 내용
  > 해당 문장

## 설정집에 없는 이름
- 이름 (○회 등장, 첫 등장 ○행)
  추가할지 알려주세요.

## 검사하지 못한 항목
- (not_checked 내용과 그 이유)
```

## 예외 & 엣지케이스

- 설정집에 나이가 없으면 나이 검사를 건너뛰고 `not_checked`에 남긴다.
  검사하지 않은 것을 문제없다고 말하지 않는다.
- 시간선 사건이 원고에 1개 이하로 등장하면 순서를 비교할 수 없어 건너뛴다.
- 미등록 이름은 2회 이상 등장한 것만 제안한다. 1회는 스쳐가는 표현일 수 있다.
- 표기 흔들림은 1회만 나와도 검출한다. 오타는 원래 드물게 나온다.
- 같은 오류가 6건 이상이면 5건만 나열하고 나머지는 건수로 요약한다.
- 설정집과 원고는 UTF-8이어야 한다. 다른 인코딩이면 오류로 알린다.
- 시간선 사건명은 원고에 그대로 나오는 표현으로 적어야 매칭된다. 표현이 다르면 검사하지 못하고 not_checked에 남는다.
- 등록명의 짧은 별칭(한 글자)과 글자가 겹치는 오타는 검출하지 못할 수 있다. 표기 흔들림 검출은 보조 수단이며 최종 확인은 사용자 몫이다.
- 능력 위반은 키워드가 인물 근처에 있는지만 본다. 실제로 그 인물이
  했는지는 판단하지 않으므로 사용자 확인이 필요하다.
